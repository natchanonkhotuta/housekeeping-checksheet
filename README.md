# ระบบมอบหมายงานและตรวจสอบงานแม่บ้าน

> Housekeeping Assignment & Check Sheet System — เว็บแอปที่ทำงานฝั่งเบราว์เซอร์ล้วน
> ไม่ต้องติดตั้งเซิร์ฟเวอร์ ไม่ต้อง build เปิดจากไฟล์ในเครื่องก็ได้ วางบน GitHub Pages ก็ได้

จัดตารางงานแม่บ้านรายเดือน มอบหมายผู้รับผิดชอบ ให้แม่บ้านติ๊กงาน หัวหน้าตรวจและอนุมัติ
พิมพ์ CHECK SHEET เป็น PDF/Excel และ **สแกนใบเช็คงานที่กาด้วยปากกากลับเข้าระบบ** ได้

## เริ่มใช้งานอย่างเร็ว

### วิธีที่ 1 — เปิดไฟล์เดียวจบ (ง่ายที่สุด)

```bash
bash build.sh
```

จะได้ `dist/hkcs-standalone.html` — ดับเบิลคลิกเปิดได้เลย ส่งต่อทางอีเมลหรือ USB ได้
ข้อมูลเก็บอยู่ในเบราว์เซอร์ของเครื่องนั้น

### วิธีที่ 2 — เปิดจากโค้ดต้นฉบับ

เปิด `index.html` ด้วยเบราว์เซอร์ได้โดยตรง (Chrome / Edge / Firefox)
หรือถ้ามีเซิร์ฟเวอร์สแตติกอยู่แล้วก็ชี้มาที่โฟลเดอร์นี้ได้เลย

### บัญชีทดลอง

รหัสผ่านทุกบัญชีคือ `1234` — **เปลี่ยนทันทีก่อนใช้งานจริง**

| ชื่อผู้ใช้ | บทบาท |
|---|---|
| `admin` | ผู้ดูแลระบบ |
| `supervisor` | หัวหน้าแม่บ้าน |
| `manager` | ผู้บริหาร |
| `recorder` | ผู้บันทึกข้อมูล (ตัวแทน) |
| `st001` … `st008` | แม่บ้าน |

## นำขึ้น GitHub Pages

1. สร้าง repository ใหม่บน GitHub แล้ว push โค้ดชุดนี้ขึ้นไป

   ```bash
   git remote add origin https://github.com/<ชื่อผู้ใช้>/<ชื่อ-repo>.git
   git push -u origin main
   ```

2. ที่ repository → **Settings → Pages → Source** เลือก **GitHub Actions**

3. ไฟล์ `.github/workflows/pages.yml` ในโปรเจกต์นี้จะ deploy ให้อัตโนมัติทุกครั้งที่ push

4. เปิดใช้งานที่ `https://<ชื่อผู้ใช้>.github.io/<ชื่อ-repo>/`

> GitHub Pages เป็นโฮสต์ไฟล์สแตติก จึงเปิดจากคอมเครื่องไหนก็ได้
> แต่ **ข้อมูลยังแยกกันตามเครื่อง** จนกว่าจะตั้งค่าคลาวด์ตามหัวข้อถัดไป

## ใช้ข้ามเครื่อง (คลาวด์)

หน้า **ตั้งค่าระบบ → การเก็บข้อมูลและการใช้ข้ามเครื่อง** เลือกได้ 4 โหมด

| โหมด | เหมาะกับ | ต้องเตรียมอะไร |
|---|---|---|
| **อัตโนมัติ** (ค่าเริ่มต้น) | ทั่วไป | ไม่ต้อง — ตรวจหาฐานข้อมูลของ Claude Artifact ให้ ถ้าไม่มีจะใช้เครื่องนี้ |
| **เก็บในเครื่องนี้** | ใช้คนเดียว / ออฟไลน์ | ไม่ต้อง |
| **Supabase** | หลายคนหลายเครื่อง ใช้ฟรีได้ | สมัคร Supabase + สร้างตาราง 1 ตาราง |
| **REST API ของตัวเอง** | มีเซิร์ฟเวอร์ในองค์กรอยู่แล้ว | endpoint ที่รับ `GET`/`PUT {base}/{key}` |

ขั้นตอนตั้ง Supabase อยู่ในไฟล์ **[docs/SETUP-CLOUD.md](docs/SETUP-CLOUD.md)** (คัดลอก SQL ไปวางได้เลย)

ทุกโหมดที่ไม่ใช่ "เก็บในเครื่องนี้" จะ **มิเรอร์ข้อมูลลงเครื่องไว้เป็นแคชเสมอ**
เน็ตหลุดก็ยังใช้งานต่อได้ แล้วค่อยกดปุ่ม 🔄 บนแถบบนเพื่อดึงข้อมูลล่าสุด

## รอบการทำงานประจำวัน

```
ต้นเดือน   หัวหน้า → มอบหมายงาน → เลือกเดือน+พื้นที่ → "สร้าง/อัปเดตตาราง" → อนุมัติตาราง
           ↓
           พิมพ์ CHECK SHEET ฟอร์มเปล่า (รายเดือน) ให้แม่บ้านถือไปติดหน้างาน
           หรือพิมพ์ "ใบเช็คงานรายวัน" แจกเป็นรายวัน

ระหว่างวัน แม่บ้าน → กาลงกระดาษ  หรือ  เปิดหน้า "งานของฉัน" กดเสร็จในมือถือ

สิ้นวัน    ผู้บันทึก → "บันทึกผลจากกระดาษ" คีย์ตามใบ
           หรือ      → "สแกนใบเช็คงาน" อัปโหลดไฟล์สแกน ระบบอ่านให้

           หัวหน้า  → "ตรวจสอบและอนุมัติ" รอบรายวัน → ตรวจผ่าน / ไม่ผ่าน (ระบุเหตุผล)
                    → "ปิดรอบ" เพื่อจัดการงานที่ไม่มีข้อสรุป

สิ้นเดือน  พิมพ์ CHECK SHEET เติมผลแล้วเก็บแฟ้ม + ส่งออก Excel เข้ารายงาน
```

## ใบเช็คงานรายวันและการสแกน

ใบเช็คงานรายวันถูกออกแบบให้อ่านกลับด้วยกล้อง/สแกนเนอร์ได้

- **หมุดดำ 4 มุม** — ใช้หาขอบกระดาษและแก้ภาพเอียง/บิด (homography)
- **แถบรหัสแผ่น 20 บิต** — เก็บ พื้นที่ · วันที่ · เดือน · ปี พร้อมบิตพาริตีกันอ่านผิด
  ระบบจึงรู้เองว่าใบนี้เป็นของใคร วันไหน โดยไม่ต้องเลือกเอง
- **ช่องกาขนาดคงที่** — ระบบนับสัดส่วนพิกเซลเข้มในกรอบ ไม่ได้อ่านลายมือ
  จึงกาเป็น ✗ หรือ ✓ อย่างไรก็ได้ ขอแค่อยู่ในกรอบ

ข้อแนะนำการสแกน

| หัวข้อ | ค่าที่แนะนำ |
|---|---|
| ความละเอียด | 200–300 dpi |
| โหมดสี | ขาวดำหรือสีเทา |
| รูปแบบไฟล์ | JPG หรือ PDF (หลายแผ่นในไฟล์เดียวได้) |
| การวางกระดาษ | ให้เห็นครบทั้งแผ่นรวมหมุด 4 มุม · กลับหัวได้ ระบบหมุนให้เอง |

ถ้าหาหมุดไม่เจอ (ถ่ายด้วยมือถือเอียงมาก, กระดาษยับ) กดปุ่ม **"ระบุมุมเอง"**
แล้วคลิกหมุดทั้ง 4 มุมเอง ระบบจะอ่านใหม่ให้

ช่องที่ระบบไม่มั่นใจจะขอบสีเหลืองพร้อมภาพที่ตัดมาจากไฟล์สแกนจริง ให้ตรวจก่อนกดบันทึก

> ⚠️ **อย่าเรียงลำดับหรือลบพื้นที่หลังพิมพ์ใบไปแล้ว** — รหัสบนแผ่นอ้างอิงลำดับพื้นที่ที่บันทึกไว้
> ถ้าลบพื้นที่ออก ใบเก่าที่พิมพ์ไปแล้วจะอ่านไม่ได้ (การจัดลำดับแสดงผลด้วยปุ่ม ▲▼ ปลอดภัย ไม่กระทบ)

```jsonc
  "planIndex": ["2026-09|ar_hr"],   // รายชื่อตารางทั้งหมด ใช้ตอนสำรองข้อมูล
  "audit":     [{ "at": "...", "by": "...", "action": "..." }]
}
```

**`plan:YYYY-MM|areaId`** — ตารางงาน 1 เดือนของ 1 พื้นที่

```jsonc
{
  "y": 2026, "m": 8, "areaId": "ar_hr",
  "status": "draft|review|approved",
  "cells": {
    "td_hr_cl01|9|morning": {
      "t": "td_hr_cl01",     // รายการงาน
      "day": 9, "p": "morning",
      "s": "st_001",          // ผู้รับผิดชอบ
      "st": "done",           // pending|assigned|doing|done|verified|failed|rework|skipped|leave
      "by": "สมหญิง ใจดี",     // ผู้ปฏิบัติงาน
      "at": "…",              // เวลาที่ถือว่าปฏิบัติงาน
      "rec": "ปราณี ธุรการ",   // ผู้คีย์ข้อมูลเข้าระบบ
      "src": "paper|scan",    // ที่มาของข้อมูล
      "vby": "มาลี วงศ์ทอง",   // ผู้ตรวจสอบ
      "note": "…"
    }
  },
  "approvals": { "plan": { "by": "…", "at": "…" } }
}
```

## การสำรองข้อมูล

- **บัญชีผู้ใช้ → สำรองข้อมูล (JSON)** — ได้ไฟล์เดียวที่รวม `master` + ตารางงาน **ทุกเดือน** ที่เคยบันทึก
- **ตั้งค่าระบบ → กู้คืนข้อมูล** — เขียนทับข้อมูลปัจจุบันทั้งหมดด้วยไฟล์สำรอง
- **ตั้งค่าระบบ → ส่งข้อมูลในเครื่องขึ้นส่วนกลาง** — ใช้ตอนย้ายจากโหมดเครื่องเดียวไปคลาวด์

แนะนำให้สำรองทุกสิ้นเดือน และเก็บไฟล์ไว้นอกเครื่องที่ใช้งาน

## ข้อจำกัดและความปลอดภัย

ระบบนี้ทำงานฝั่งเบราว์เซอร์ทั้งหมด ไม่มีเซิร์ฟเวอร์ตรวจสอบสิทธิ์ จึงต้องเข้าใจข้อจำกัดต่อไปนี้

- **การล็อกอินเป็นการควบคุมการใช้งาน ไม่ใช่การป้องกันระดับความปลอดภัย**
  รหัสผ่านเก็บเป็นค่าแฮช SHA-256 (ไม่มี salt) และตรวจสอบในเบราว์เซอร์
  ผู้ที่เข้าถึงฐานข้อมูลได้โดยตรงย่อมอ่านและแก้ไขข้อมูลได้ — เหมาะกับการใช้ภายในองค์กร
  **ไม่ควรใส่ข้อมูลที่เป็นความลับสูงหรือข้อมูลส่วนบุคคลที่อ่อนไหว**
- ถ้าใช้ Supabase ให้ใช้ **anon key** เท่านั้น อย่าใส่ service key ลงในหน้าเว็บ
  และตั้ง Row Level Security ตามที่แนะนำใน `docs/SETUP-CLOUD.md`
- โหมดคลาวด์เป็นแบบ **เขียนทีหลังทับ (last write wins)** —
  ถ้าสองคนแก้ตารางเดือนเดียวกันพื้นที่เดียวกันพร้อมกัน คนที่กดบันทึกทีหลังจะทับ
  แนะนำให้แบ่งกันดูแลคนละพื้นที่ และกดปุ่ม 🔄 ก่อนเริ่มแก้
- โหมด "เก็บในเครื่องนี้" ใช้ `localStorage` — **ล้างข้อมูลเบราว์เซอร์แล้วข้อมูลหาย**
  ให้สำรองไฟล์ JSON เป็นระยะ
