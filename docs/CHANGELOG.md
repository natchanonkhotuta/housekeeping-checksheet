# บันทึกการเปลี่ยนแปลง

## 1.4.2

แก้ปัญหา "มอบหมายงานแล้วแต่ตารางไม่ตรงกับที่มอบหมาย"

### ต้นเหตุ

`staffOffOn()` ตรวจเฉพาะวันหยุดและวันลา**รายวัน** แต่ไม่เคยดู **สถานะพนักงาน**
คนที่ถูกตั้งเป็น "ลาพัก" หรือ "พ้นสภาพ" จึงยังถูกมอบหมายงานตามปกติ
และชื่อถูกพิมพ์ลงใบเช็คงานรายวันด้วย ทั้งที่ไม่ได้อยู่ปฏิบัติงานแล้ว

ซ้ำร้ายคือ การเปลี่ยน "พื้นที่รับผิดชอบ" ของแม่บ้าน ไม่ได้ย้อนกลับไปแก้ตารางที่สร้างไว้แล้ว
ตารางจึงค้างชื่อเดิมไว้โดยไม่มีอะไรเตือน

### แก้ไข

- เพิ่ม `staffInactive()` แยกจาก `staffOffOn()` — สถานะถาวร (ลาพัก/พ้นสภาพ)
  แยกจากวันหยุดรายวัน เพื่อไม่ให้รายงานย้อนหลังเพี้ยน
  (งานที่เคยทำจริงตอนยังปฏิบัติงานอยู่ต้องไม่กลายเป็น "วันหยุด" ทั้งเดือน)
- `generatePlan()` ข้ามคนที่ไม่ได้ปฏิบัติงานแล้ว และหาผู้ทดแทนให้อัตโนมัติ
- หน้ามอบหมายงานขึ้น**แถบแดง**เมื่อมีช่องที่เป็นชื่อคนลาพัก/พ้นสภาพ
  พร้อมปุ่มแทนที่ด้วยผู้รับผิดชอบพื้นที่นั้นในคลิกเดียว
- เพิ่มปุ่ม **“👥 ตั้งผู้รับผิดชอบตามพื้นที่”** — ดันข้อมูล "ใครดูแลพื้นที่นี้"
  ลงตารางทั้งเดือนได้ พร้อมแสดงว่าตอนนี้ตารางมีชื่อใครอยู่บ้างและใครดูแลพื้นที่นี้จริง

### บั๊กที่เจอระหว่างแก้

- **`cellHasResult()` นับ "หมายเหตุ" เป็นผลการปฏิบัติงาน** — `generatePlan()` เขียนหมายเหตุ
  อัตโนมัติอยู่แล้ว (เช่น "ทดแทน X (ลาป่วย)") ช่องเกือบทั้งเดือนจึงถูกถือว่าบันทึกผลแล้ว
  และแตะไม่ได้เลยทั้งตอนอัปเดตตาราง ตั้งผู้รับผิดชอบใหม่ และล้างตาราง
  แก้ให้ดูเฉพาะร่องรอยการบันทึกผลจริง (`by` / `at` / `rec` / `vby`)
- **“มอบหมายเป็นชุด” เปลี่ยนชื่อผู้ปฏิบัติงานย้อนหลังได้** — ตอนนี้ข้ามช่องที่บันทึกผลแล้ว
  และรายงานจำนวนช่องที่คงไว้ให้เห็น

## 1.4.1

แก้บั๊กที่พบจากการใช้งานจริง

- **ชั้นที่ 1 ขึ้นเลข 3 ในแถว “ตึกที่ทำ”** — พื้นที่ที่ยังไม่ได้กรอกเลขย่อจะถูกไล่เลขตามลำดับ
  ทำให้ ชั้นที่ 1 ได้เลข 3 ซึ่งไม่ตรงกับที่คนเรียกกันหน้างาน
  แก้เป็น: ชื่อที่เป็น “ชั้นที่ N” ใช้เลขชั้นนั้นเป็นเลขย่ออัตโนมัติ (ชั้นที่ 1 → 1, ชั้นที่ 4 → 4)
  ชื่ออื่นค่อยไล่เลขว่างที่เหลือ และเลขที่กรอกเองยังมาก่อนเสมอ
  ตัวเลขในชื่ออื่นไม่ถูกดึงมาใช้ผิด เช่น “ปิดตึก (ตั้งแต่ 17.00 น.)” ไม่กลายเป็นเลข 17
- **เปอร์เซ็นต์เทียบเป้าหมายต่ำผิดปกติ** — เดิมนับงานทั้งเดือนรวมวันที่ยังมาไม่ถึง
  ต้นเดือนจึงได้เลขอย่าง “13 จาก 969 · 1%” เสมอ
  แก้เป็นนับเฉพาะวันที่ผ่านมาแล้ว และไม่นับวันหยุด/วันลาของคนนั้น
- **เพิ่มตัวบอกความครบของข้อมูล** — แสดง “มีข้อมูล X จาก Y วันทำงาน”
  และขึ้นแถบเตือนเมื่อยังคีย์ข้อมูลไม่ครบ เพื่อไม่ให้เข้าใจผิดว่าแม่บ้านทำงานได้น้อย
  ทั้งที่จริงคือยังไม่ได้บันทึกผล
- **ส่งออก Excel พังเมื่อมีแม่บ้านชื่อซ้ำกัน** — ชื่อชีตซ้ำทำให้ไลบรารีโยน error
  ตอนนี้ต่อเลขท้ายให้อัตโนมัติ แก้ทั้งรายงานรายบุคคลและ CHECK SHEET

## 1.4.0

รายงานรายเดือนรวมแถวตามชื่องาน เพิ่มแถวตึกที่ทำ และกันข้อมูลเก่าหายตอนอัปเดตตาราง

### รายงานสรุปรายเดือนรายบุคคล

- **รวมแถวตามชื่องาน** — งานชื่อเดียวกันที่ทำคนละตึกยุบเป็นแถวเดียว
  ไม่ต้องมีชื่อพื้นที่ห้อยใต้ทุกแถวอีก ตารางสั้นลงและอ่านง่ายขึ้นมาก
  เรียงตามลำดับงานมาตรฐาน (ใช้ลำดับที่น้อยที่สุดของงานชื่อนั้น)
- **แถว “ตึกที่ทำ” บนสุดของตาราง** — แต่ละวันแสดงเลขย่อของตึกที่ไปทำ
  วันที่ทำหลายตึกแสดง `4,5` เรียงจากเลขน้อยไปมาก วันหยุดแสดง `—`
- **แถบผลงานเทียบเป้าหมาย** — `ทำได้ X จาก Y จุด-วัน (Z%)` พร้อมจำนวนวันแยกรายตึก
  เป้า = งานที่ตารางมอบหมายให้คนนั้นรวมทุกพื้นที่ · ทำได้ = งานที่ทำจริงรวมที่บันทึกเพิ่มเอง
  นับเป็นจุด-วัน (งาน 1 อย่าง x 1 วัน = 1 หน่วย งานทั้งเช้าบ่ายนับเป็น 1)
- มีคำอธิบายเลขตึกกำกับทั้งบนหน้าจอ ใบพิมพ์ และไฟล์ Excel

### เลขย่อพื้นที่

- เพิ่มช่อง **เลขย่อ** ที่หน้าจัดการพื้นที่ — กรอกเลขสั้น ๆ แทนตึกได้เอง (ชั้น 4 → `4`)
- พื้นที่ที่ยังไม่ได้กรอกจะได้เลขว่างตัวถัดไปอัตโนมัติ **โดยไม่ชนกับเลขที่กรอกเอง**
  (ตอนแรกใช้ลำดับพื้นที่ตรง ๆ แล้วพบว่าชนกันจริงตอนทดสอบ — แก้แล้ว)
- กรอกเลขซ้ำกับพื้นที่อื่นไม่ได้ ระบบเตือนและไม่ให้บันทึก

### ป้องกันข้อมูลตารางหาย

- **“สร้าง/อัปเดตตาราง” ไม่ลบข้อมูลเดิมอีกต่อไป** — เดิมมีตัวเลือกเขียนทับที่ล้างทั้งเดือน
  ตอนนี้เติมเฉพาะช่องที่ยังไม่มี และ**ไม่แตะช่องที่บันทึกผลไปแล้วเด็ดขาด**
  ถ้าเลือกอัปเดตผู้รับผิดชอบ จะอัปเดตได้เฉพาะช่องที่ยังไม่มีผล ตั้งแต่วันที่ที่ระบุเป็นต้นไป
- **ปุ่ม “ล้างตาราง” แยกออกมาต่างหาก** เลือกขอบเขตได้ 4 แบบ
  ตั้งแต่ปลอดภัยที่สุด (เฉพาะวันข้างหน้าที่ยังไม่บันทึกผล) ไปจนถึงล้างทั้งเดือน
  พร้อมบอกจำนวนช่องที่จะถูกลบและเตือนเมื่อตัวเลือกนั้นจะลบผลที่บันทึกไว้

## 1.3.0

สถิติรายวันรายบุคคล และรายงานสรุปรายเดือนแบบใหม่

### ปัญหาที่แก้

รายงานเดิมอ่านข้อมูลจากตารางงานทีละพื้นที่ พอแม่บ้านไม่ได้ทำตามพื้นที่ที่วางแผนไว้
เช่นวันนี้ไปช่วยอีกชั้นหนึ่ง งานวันนั้นจะไม่ปรากฏในรายงานของพื้นที่หลัก — ข้อมูลตกหล่น

เวอร์ชันนี้เพิ่มชั้นข้อมูลที่จัดกลุ่มตาม **คน + วัน** แทนที่จะยึดพื้นที่
`monthWorkIndex()` กวาดตารางงานของทุกพื้นที่ในเดือนนั้นครั้งเดียว
แล้วจัดเป็นดัชนี `คน|วัน` ให้ทุกหน้าจอใช้ร่วมกัน

### เพิ่มใหม่

- **หน้า “บันทึกประจำวัน”** (ผู้ดูแล · หัวหน้าแม่บ้าน · ผู้บันทึก)
  เลือกวันที่แล้วเห็นแม่บ้านทุกคน พร้อมงานที่ระบบรวมมาจากทุกพื้นที่ให้แล้ว
  แก้ได้ 3 อย่าง — เพิ่มงานที่ระบบไม่รู้ (เลือกได้เฉพาะพื้นที่ที่คนนั้นรับผิดชอบ),
  เอางานที่ไม่ได้ทำจริงออก, และใส่คอมเมนต์ของคนนั้นในวันนั้น
  สถานะหยุด/ลาดึงจากปฏิทินให้เอง และกดสลับเป็นปฏิบัติงานได้เมื่อมาทำจริง
- **หน้า “สรุปรายเดือนรายบุคคล”** (ทุกบทบาทที่ดูรายงานได้)
  หนึ่งคนหนึ่งตาราง · แถวคือจุดที่คนนั้นทำจริงทั้งเดือนรวมทุกพื้นที่ · คอลัมน์คือวันที่
  ติ๊ก ✓ เฉพาะวันที่ทำ (✗ เมื่อตรวจไม่ผ่าน) วันที่ไม่ได้ทำจุดนั้นเว้นว่าง
  คอมเมนต์รายวันแสดงเป็นเชิงอรรถใต้ตาราง พิมพ์ A4 แนวนอนและส่งออก Excel ได้ (หนึ่งคนหนึ่งชีต)
- **เอกสารใหม่ `daily:YYYY-MM`** เก็บเฉพาะส่วนต่างจากที่ระบบรวมได้เอง (`add` / `rm` / `cm` / `st`)
  ไม่เก็บข้อมูลซ้ำ จึงไม่ขัดกันเมื่อคีย์ผลจากกระดาษหรือสแกนเพิ่มทีหลัง
- สำรองข้อมูล · กู้คืน · ส่งข้อมูลขึ้นส่วนกลาง · และปุ่มซิงก์ รวมบันทึกประจำวันด้วยแล้ว

## 1.2.0

ตั้งค่าคลาวด์ครั้งเดียวตอน deploy และรองรับ Netlify

- **`assets/config.js`** — ไฟล์ตั้งค่ากลางไฟล์เดียว กรอก Supabase URL/anon key ที่นี่ครั้งเดียว
  แล้วทุกเครื่องที่เปิดเว็บจะใช้ค่านั้นทันที ไม่ต้องให้ผู้ใช้กรอกเอง
  ตั้ง `lockStorage: true` เพื่อล็อกไม่ให้ผู้ใช้เปลี่ยนโหมดเก็บข้อมูลเอง
- **ลำดับความสำคัญของการตั้งค่า** — config ที่ล็อกไว้ → ค่าที่ผู้ใช้ตั้งเอง →
  config แบบไม่ล็อก (เป็นค่าเริ่มต้น) → ฐานข้อมูล Claude Artifact → เก็บในเครื่อง
- **`netlify.toml` + `netlify-build.sh`** — deploy ขึ้น Netlify ได้ตรง ๆ
  เขียน `config.js` จาก Environment variables (`SUPABASE_URL`, `SUPABASE_ANON_KEY`, …) ตอน build
  และตั้ง `Cache-Control: no-store` ให้ `config.js`/`index.html` เพื่อให้เปลี่ยนค่าแล้วมีผลทันที
- หน้าตั้งค่าระบบแสดงป้ายบอกที่มาของการตั้งค่า และปิดช่องกรอกเมื่อถูกล็อกไว้
- ตั้งชื่อบริษัท/ฝ่าย/รหัสเอกสารเริ่มต้นจาก config ได้ (ใช้เฉพาะตอนสร้างข้อมูลครั้งแรก)

## 1.1.0

จัดโครงสร้างโปรเจกต์ใหม่ แก้บั๊ก และเพิ่มการใช้งานข้ามเครื่อง

### แก้บั๊ก

**1. แม่บ้านเข้าหน้าพิมพ์ CHECK SHEET ไม่ได้เลย**
บทบาทแม่บ้านมีสิทธิ์ `print.self` แต่เมนูตรวจด้วย `can('print')` ซึ่งไม่รู้จักสิทธิ์แบบมีจุด
ทั้งที่หน้าพิมพ์เขียนรองรับกรณีแม่บ้านไว้แล้ว
อาการเดียวกันนี้ยังทำให้ **หัวหน้าแม่บ้านเปิดหน้าวันหยุด/วันลาไม่ได้** ทั้งที่มีสิทธิ์ `holiday.edit`
และ **หัวหน้า/ผู้บริหาร/ผู้บันทึก เปิดหน้าแม่บ้าน พื้นที่ รายการงานไม่ได้** ทั้งที่มีสิทธิ์ `.view`

แก้โดยแยกการตรวจสิทธิ์เป็น 2 ชั้น — `ROUTE_PERMS` + `canAny()` สำหรับ "เปิดหน้าจอ"
และ `can()` แบบตรงตัวสำหรับ "แก้ไข" พร้อมเพิ่มด่านตรวจสิทธิ์ใน `renderRoute()`
เพื่อกันการเข้าหน้าจอโดยตรงโดยไม่มีสิทธิ์

**2. สแกนใบเช็คงานข้ามเดือนไม่ได้**
`handleFiles()` โหลดตารางเฉพาะเดือนที่เปิดค้างอยู่ แต่ `extractMarks()` อ่านเดือนจากรหัสบนแผ่น
สแกนใบของเดือนอื่นจึงขึ้นว่า "ยังไม่มีตารางงาน…" ทั้งที่มีข้อมูลอยู่
แก้โดยให้ `applyCorners()` ถอดรหัสแผ่นก่อน แล้ว `await loadPlan()` ของเดือนนั้นก่อนถอดผล

**3. การตัดภาพช่องในหน้าตรวจผลสแกนช้ามาก**
`cropCell()` เรียก `getImageData(x, y, 1, 1)` ทีละพิกเซล ≈ 968 ครั้งต่อช่อง คูณด้วยหลายสิบช่อง
แก้โดยดึง `ImageData` ของทั้งภาพครั้งเดียวแล้วเก็บใน `WeakMap` — วัดได้ 31 ms ต่อ 40 ช่อง

**4. สำรองข้อมูลบนคลาวด์ได้ไม่ครบ**
`backupAll()` ในโหมดคลาวด์ดัมป์เฉพาะตารางที่โหลดไว้ในหน่วยความจำของ session นั้น
เดือนที่ยังไม่ได้เปิดดูจะหายจากไฟล์สำรอง
แก้โดยเพิ่ม `planIndex` ในข้อมูลหลัก บันทึกทุกครั้งที่ `savePlan()` และรวบรวมจากทั้ง
`planIndex` + แคชในเครื่อง + การ query ฝั่งคลาวด์

**5. หน้ากระดาษของใบเช็คงานรายวันผิดแนว**
CSS ตั้ง `@page` เป็น A4 แนวนอนไว้ตายตัว แต่ใบเช็คงานรายวันขนาด 190×265 มม. เป็นแนวตั้ง
พิมพ์ออกมาจึงล้นหน้า แก้โดยสลับ `@page` ตามชนิดเอกสารที่กำลังพิมพ์

### แก้เพิ่มระหว่างทาง

- **ใบตรวจรอบวัน/สัปดาห์ถูกตัวบล็อก pop-up ขวาง** — `printRound()` เปิดหน้าต่างใหม่ด้วย
  `window.open()` ซึ่งถูกบล็อกในหลายเบราว์เซอร์และในหน้าเว็บที่ฝังใน iframe
  เปลี่ยนมาพิมพ์ในหน้าเดิมผ่าน `printDocument()` แทน
- **ใบเช็คงานรายวันข้ามเดือนไม่แสดง** — `drawDailySheets()` ข้ามวันที่อยู่ในเดือนที่ยังไม่โหลด
  ตอนนี้โหลดทุกเดือนในช่วงที่เลือกให้ก่อน และจำกัดช่วงไม่เกิน 62 วัน
- **บัญชีแม่บ้านที่ไม่ได้ผูกข้อมูลแม่บ้าน เห็นงานของทุกคน** — ตอนนี้แจ้งเตือนให้ไปผูกก่อน
  และหน้าเพิ่มผู้ใช้บังคับให้ผูกเมื่อเลือกบทบาทแม่บ้าน
- **รหัสแผ่นบนใบเช็คงานเปลี่ยนเมื่อจัดลำดับพื้นที่ใหม่** — เดิมอ้างอิงลำดับแสดงผล (`order`)
  ทำให้ใบที่พิมพ์ไปแล้วอ่านผิดพื้นที่หลังกดปุ่ม ▲▼ เปลี่ยนมาอ้างอิงลำดับที่บันทึกไว้จริงแทน
- **ชื่อผู้ใช้ซ้ำเมื่อเพิ่มแม่บ้าน** — ตอนนี้ต่อเลขท้ายให้อัตโนมัติจนกว่าจะไม่ซ้ำ
- **`leaveDialog` พังถ้าแม่บ้านถูกลบไปแล้ว** — เพิ่มการตรวจก่อนอ่าน `mainAreaId`
- **`ผู้บันทึก`/`ตรวจไม่ผ่าน` ทำให้ประวัติผู้ปฏิบัติงานสับสน** — แยกฟิลด์ชัดเจน
  `by` = ผู้ปฏิบัติงาน · `rec` = ผู้คีย์ข้อมูล · `vby` = ผู้ตรวจสอบ · `src` = ที่มาของข้อมูล
- ล้างโค้ดที่ไม่ทำงาน — `forEach` เปล่าใน `dailyRows()`, `text-align` ซ้ำใน `.navitem`,
  หมายเลขหัวข้อซ้ำในคอมเมนต์, ตัวแปรที่ประกาศแล้วไม่ได้ใช้

### เพิ่มใหม่

- **โหมดเก็บข้อมูลแบบเลือกได้ 4 แบบ** — อัตโนมัติ / เก็บในเครื่อง / Supabase / REST API ของตัวเอง
  พร้อมปุ่มทดสอบการเชื่อมต่อ ปุ่มดึงข้อมูลล่าสุด และปุ่มส่งข้อมูลในเครื่องขึ้นส่วนกลาง
- **แคชออฟไลน์** — ทุกโหมดคลาวด์มิเรอร์ข้อมูลลง `localStorage` เสมอ
  เน็ตหลุดยังใช้ต่อได้ และดึงข้อมูลใหม่อัตโนมัติเมื่อกลับมาออนไลน์
- **ลบพื้นที่ / ลบแม่บ้าน / ลบผู้ใช้** พร้อมการตรวจการอ้างอิง
  และเสนอทางเลือกที่ปลอดภัยกว่า (ปิดใช้งาน / ตั้งเป็นพ้นสภาพ) เมื่อการลบจะทำให้ประวัติเสียหาย
- **คำใบ้แป้นพิมพ์ในหน้าคีย์ผลจากกระดาษ** — `1`=✓ `2`=✗ `3`=– `0`=ล้าง ลูกศรเลื่อนช่อง
- ส่งออก Excel ของรายงานเพิ่มคอลัมน์ ผู้คีย์ข้อมูล และที่มาของข้อมูล (คีย์มือ/สแกน)
- `build.sh` สร้างไฟล์เดียวจบสำหรับแจกจ่าย และเวอร์ชันสำหรับวางเป็น Artifact
