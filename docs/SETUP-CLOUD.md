# ตั้งค่าให้ใช้ข้ามเครื่องได้ (คลาวด์)

ค่าเริ่มต้นของระบบเก็บข้อมูลไว้ในเบราว์เซอร์ของเครื่องนั้น ๆ
ถ้าต้องการให้หัวหน้า ผู้บันทึก และแม่บ้านเห็นข้อมูลชุดเดียวกันจากคนละเครื่อง
ให้เลือกวิธีใดวิธีหนึ่งด้านล่าง แล้วตั้งค่าที่หน้า **ตั้งค่าระบบ → การเก็บข้อมูลและการใช้ข้ามเครื่อง**

---

## วิธีที่ 1 — Supabase (แนะนำ ใช้ฟรีได้)

Supabase มีแพ็กเกจฟรีที่เพียงพอกับระบบนี้มาก
ข้อมูลทั้งหมดของระบบเก็บเป็นตาราง key/value เพียงตารางเดียว

### 1. สร้างโปรเจกต์

1. สมัครที่ <https://supabase.com> แล้วสร้าง project ใหม่
2. เลือก region ที่ใกล้ที่สุด (เช่น Singapore) เพื่อให้เร็ว

### 2. สร้างตาราง

เข้าเมนู **SQL Editor** แล้ววางคำสั่งนี้ กด Run

```sql
-- ตารางเก็บข้อมูลของระบบแม่บ้าน
create table if not exists public.hkcs_kv (
  key        text primary key,
  value      jsonb not null,
  updated_at timestamptz not null default now()
);

alter table public.hkcs_kv enable row level security;

-- อนุญาตให้อ่าน/เขียนด้วย anon key
-- (ระบบควบคุมสิทธิ์ผู้ใช้ในตัวแอป — ดูหัวข้อ "ข้อควรระวัง" ด้านล่าง)
create policy "hkcs read"   on public.hkcs_kv for select using (true);
create policy "hkcs insert" on public.hkcs_kv for insert with check (true);
create policy "hkcs update" on public.hkcs_kv for update using (true) with check (true);
```

### 3. คัดลอกค่าที่ต้องใช้

เข้า **Project Settings → API** แล้วคัดลอก

| ช่องในแอป | ค่าที่คัดลอกมา |
|---|---|
| Supabase Project URL | `Project URL` เช่น `https://abcdefgh.supabase.co` |
| anon public key | `anon` `public` (ตัวยาว ๆ ขึ้นต้นด้วย `eyJ…`) |
| ชื่อตาราง | `hkcs_kv` |

> ⚠️ ใช้ **anon public** เท่านั้น
> ห้ามใช้ `service_role` เด็ดขาด เพราะมันจะฝังอยู่ในหน้าเว็บให้ทุกคนเห็น

### 4. ตั้งค่าในแอป

1. เข้าสู่ระบบด้วยบัญชีผู้ดูแลระบบ → **ตั้งค่าระบบ**
2. หัวข้อ **การเก็บข้อมูลและการใช้ข้ามเครื่อง** → เลือก **Supabase**
3. กรอก URL, anon key, ชื่อตาราง
4. กด **ทดสอบการเชื่อมต่อ** — ต้องขึ้น "เชื่อมต่อสำเร็จ ✓"
5. กด **บันทึกและเชื่อมต่อใหม่**
6. ถ้าเครื่องนี้มีข้อมูลอยู่แล้วและต้องการยกขึ้นคลาวด์ กด **ส่งข้อมูลในเครื่องขึ้นส่วนกลาง**

### 5. ตั้งค่าเครื่องอื่น

เปิดเว็บเดียวกัน → ตั้งค่าระบบ → กรอก URL/key/ตาราง ชุดเดียวกัน → บันทึก
เท่านี้ทุกเครื่องก็เห็นข้อมูลชุดเดียวกัน

## วิธีที่ 2 — REST API ของตัวเอง

ถ้าองค์กรมีเซิร์ฟเวอร์อยู่แล้ว ทำ endpoint ที่รองรับ 2 คำสั่งนี้ก็พอ

| คำสั่ง | ความหมาย | ผลลัพธ์ |
|---|---|---|
| `GET {base}/{key}` | อ่านค่า | ตัว JSON ของค่านั้น หรือสถานะ `404` ถ้าไม่มี |
| `PUT {base}/{key}` | เขียนค่า (สร้างใหม่หรือทับของเดิม) | สถานะ `2xx` |

`{key}` ที่ระบบใช้มี 2 แบบ

- `master` — ข้อมูลหลักทั้งหมด
- `plan:2026-09|ar_hr` — ตารางงาน 1 เดือนของ 1 พื้นที่ (ผ่าน URL encoding แล้ว)

ถ้าต้องยืนยันตัวตน ให้กรอกชื่อ header และค่าของ header ในหน้าตั้งค่า
เช่น `Authorization` / `Bearer xxxxx`

ตัวอย่าง Express อย่างย่อ

```js
const store = new Map();                  // ใช้งานจริงควรต่อฐานข้อมูล

app.get('/kv/:key', (req, res) => {
  const v = store.get(req.params.key);
  if (v === undefined) return res.sendStatus(404);
  res.json(v);
});

app.put('/kv/:key', express.json({ limit: '8mb' }), (req, res) => {
  store.set(req.params.key, req.body);
  res.sendStatus(204);
});
```

ตั้งค่า CORS ให้อนุญาต origin ของหน้าเว็บ พร้อม method `GET, PUT` และ header `Content-Type`

## วิธีที่ 3 — Claude Artifact (ไม่ต้องตั้งค่าอะไรเลย)

ถ้าเปิดระบบผ่านลิงก์ Artifact ของ Claude ระบบจะตรวจพบฐานข้อมูลของ Artifact เอง
และใช้เป็นที่เก็บข้อมูลกลางให้อัตโนมัติ (โหมด "อัตโนมัติ")

- ไม่ต้องสมัครอะไรเพิ่ม เปิดลิงก์จากคอมเครื่องไหนก็เห็นข้อมูลชุดเดียวกัน
- ผู้ที่จะเข้าใช้ต้องได้รับสิทธิ์ให้เปิด Artifact นั้น และอยู่ในองค์กรเดียวกัน
- เหมาะกับการใช้ภายในทีมเล็ก ๆ หรือทดลองใช้ก่อนตั้ง Supabase จริง

## ข้อควรระวังร่วมกันทุกวิธี

**การควบคุมสิทธิ์อยู่ในตัวแอป ไม่ใช่ที่ฐานข้อมูล**
ใครที่ได้ URL และ anon key ไป ย่อมอ่านและเขียนข้อมูลในตารางได้โดยตรงโดยไม่ผ่านหน้าล็อกอิน
ระบบนี้จึงเหมาะกับข้อมูลปฏิบัติงานภายในองค์กร ไม่ควรใส่ข้อมูลที่เป็นความลับสูง

ถ้าต้องการความปลอดภัยระดับสูงกว่านี้ ให้ทำอย่างใดอย่างหนึ่ง

- เปิด Supabase Auth แล้วแก้ policy ให้ผูกกับ `auth.uid()` (ต้องแก้โค้ดฝั่งแอปเพิ่ม)
- วางระบบไว้หลัง VPN หรือ intranet ขององค์กร
- ใช้วิธีที่ 2 แล้วตรวจสอบสิทธิ์ที่เซิร์ฟเวอร์ของตัวเอง

**การเขียนพร้อมกันเป็นแบบเขียนทีหลังทับ**
ถ้าสองคนแก้ตารางเดือนเดียวกัน พื้นที่เดียวกัน พร้อมกัน คนที่บันทึกทีหลังจะทับ
แนะนำให้แบ่งกันดูแลคนละพื้นที่ และกดปุ่ม 🔄 บนแถบบนก่อนเริ่มแก้ทุกครั้ง

**เน็ตหลุดยังใช้งานได้**
ทุกโหมดคลาวด์จะมิเรอร์ข้อมูลลงเครื่องเป็นแคชเสมอ
ถ้าต่อส่วนกลางไม่ได้ ระบบจะแจ้งเตือนและใช้แคชแทน — ข้อมูลที่บันทึกช่วงนั้นอยู่ในเครื่อง
เมื่อกลับมาต่อได้แล้วให้กด **ส่งข้อมูลในเครื่องขึ้นส่วนกลาง** เพื่อยืนยันการซิงก์
